# 安全威胁模型

[English version](security-threat-model.md)

## 范围与假设

LocalBridge 是面向可信私有局域网的本地优先协作服务。“可信局域网”只会降低暴露面，并不代表流量、发现报文或每台主机都
可信。路由器端口转发、公有云暴露和敌对公共 Wi-Fi 不属于受支持的部署模式。

运行 LocalBridge 的操作系统账号被视为可信。完全失陷的已配对设备或 Windows 账号能够访问用户授权给它的内容；这超出
单进程防护边界，但撤销、有界保留和可观察动作可以限制损害。

## 资产

- 剪贴板文本和未来富剪贴板格式。
- 分享/接收的文件字节、名称、哈希、路径和传输历史。
- 管理 Bearer Token、配对码、peer Token 和未来私钥。
- 设备身份、对端注册表、能力、网络地址和最后在线元数据。
- 控制开机启动、Explorer 集成、自动接收和通知的设置。
- 批准上传、打开 URL 或调用未来插件等动作的完整性。

## 信任边界

| 边界 | 信任级别 | 必需控制 |
|---|---|---|
| 回环 GUI 与原生外壳 | 本地管理 | Origin/回环检查、有界请求、不反射密钥 |
| 已认证管理客户端 | 最高远程权限 | 管理 Token 作用域、TLS、审计元数据、peer Token 不可替代 |
| 已配对对端 | 只允许内容传输 | 每设备凭据、过期/撤销、能力检查、TLS 指纹固定 |
| 公开分享/接收 URL | 仅一个能力 | 随机 Token、过期、路径隔离、大小/Range 校验、撤销 |
| UDP 发现 | 不可信提示 | 不含凭据、不自动配对、有界解析、人工核验 |
| 持久化存储 | 敏感本地状态 | 严格权限、原子写、保留策略、迁移与备份策略 |
| 未来插件/客户端 | 显式授权 | Manifest、最小权限、版本契约、敏感动作确认 |

## 攻击者与滥用场景

1. 被动局域网观察者从 HTTP 捕获剪贴板、文件或 Bearer Token。
2. 主动局域网攻击者伪造发现、重定向客户端、替换证书或迫使安全对端降级到 HTTP。
3. 恶意已配对设备使用自身 Token 调用仅管理方接口，或查看其他对端的凭据/配置。
4. 泄漏的能力 URL 在过期前被重放或传播到预期局域网之外。
5. 构造名称、路径、Range、JSON 或超大响应，尝试目录穿越、覆盖、内存/磁盘耗尽或解析歧义。
6. 恶意网页通过类似 CSRF 的浏览器行为攻击回环管理接口。
7. 日志、诊断、通知、历史、备份或支持包泄漏内容或密钥。
8. 中断写入或升级损坏注册表，使凭据/动作处于歧义状态。
9. 未来插件、Webhook 或自动化规则越过声明权限，或形成动作循环。

## 安全不变量

- 发现永不授予信任；只有配对或显式本机管理可以改变信任状态。
- 凭据和载荷正文永不写入日志、列表 API 或通知。
- 管理凭据与 peer 凭据拥有不同授权作用域。
- 安全对端在 TLS、证书或指纹失败后绝不回退明文。
- HTTP 客户端不会跟随携带凭据、跨来源或跨 scheme 的重定向。
- 公开能力 Token 只授权一个有边界的分享/接收资源，并且会过期。
- 文件写入始终位于受控目录；客户端文件名不能选择任意目标路径。
- 关闭自动接收时，批准前不接收上传字节。
- 解析器、请求、响应、文件数量、字节数、历史和保留期都必须有边界。
- 持久化修改必须原子完成，或在失败时回滚内存状态。
- 未来插件和自动化只有获得声明权限后才能访问资源。

## 已实现控制

- 可选管理 Bearer 认证、请求 ID 和仅记录元数据的结构化日志。
- 显式配对、持久化且会过期的 peer Token、有界轮换重叠期和撤销。
- 仅管理方可读的脱敏生效配置诊断。
- 不可信且有大小边界的 UDP 发现和能力协商。
- 随机且会过期的文件能力 URL、安全受控路径、Range/Content-Range 校验、校验和、接收确认和跨重启传输状态。
- 带迁移检查和数量/保留边界的原子式版本化存储。
- 不需要提权的 Windows 当前用户注册表集成，事件不携带载荷或路径。
- 启用时 TLS 1.2+ 仅 HTTPS 启动、叶证书精确固定、拒绝重定向，secure peer 不回退 HTTP（Sprint 2.8）。
- 不覆盖目标的脱敏支持包，排除秘密、身份、路径、TLS 材料、载荷与状态正文。
- Windows 当前用户 DPAPI 保护引用式凭据和注册表 v4 peer Token，密文绑定用途，v3 迁移原子且关闭式失败（Sprint 2.9）。

## v1.0 前的开放风险

- TLS 为兼容性仍可显式关闭；继续使用 HTTP 的部署会向主动局域网攻击者暴露 Token 与内容，但 secure peer 本身不会降级。
- macOS Keychain 与 Linux Secret Service 尚未实现。这些平台必须显式选择 `disabled` 明文兼容模式，否则拒绝启动；Windows 用户
  也可能暂时保留旧 YAML 内联值，直到手动改为引用。
- 配对码配置和首次证书指纹核验还没有完善、用户可验证的仪式。
- 共享限流、连接配额、磁盘预留和恶意对端退避尚未完整实现。
- 浏览器 Origin/CSRF 策略与 Content Security Policy 仍需专项审查。
- 尚无签名安装/更新通道、依赖 SBOM、模糊测试计划或外部审计。
- 隐私删除验证与事件响应/撤销手册尚未实现。

## TLS 与配对验收标准

- TLS 配置在模块启动前校验；证书/私钥不完整或不可读时关闭式失败。
- 服务端声明叶证书 SHA-256 指纹作为元数据，但绝不把它本身当成身份证明。
- 安全对端持久化已核验指纹，每次请求都执行精确证书固定。
- 错误/变化证书、TLS 错误和重定向会让任务失败，不进行 HTTP 重试。
- 旧 HTTP 对端必须明显标记，并通过显式重新配对/升级才能变为安全。
- 证书续期必须通过已认证、用户可观察的指纹更新，使用有边界重叠或显式批准；禁止静默替换。
- iPhone/Windows 信任安装和私有 CA 指南必须形成文档并人工验证。

## v1.0 安全发布门禁

在 `v1.0.0` 前还必须完成并记录：

1. 安全默认传输决策，以及旧 HTTP 对端迁移。
2. 静态凭据保护或有文档的平台凭据库等价方案。
3. 每路由限流/大小限制、连接/磁盘配额和对抗测试。
4. 每个浏览器可达管理修改接口的 CSRF/Origin/CSP 审查。
5. 发现、配置、Range、上传状态和协议信封的模糊测试。
6. 依赖审计/SBOM、签名可复现产物、更新回滚和迁移演练。
7. 脱敏支持包、隐私删除测试和事件响应/撤销手册。
8. 跨客户端一致性测试，证明认证、拒绝降级和能力回退。
