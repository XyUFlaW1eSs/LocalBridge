# 文件分享产品计划

[English](file-sharing-product-plan.md)

## 产品决策

文件流程不建模为“把文件放进剪贴板”，而是一个可断点续传、可过期的传输会话。
Windows 应用创建一次分享，接收设备扫描二维码或打开短 URL，移动端网页展示文件并调用
浏览器原生的下载/上传能力。

UI 采用 Web-first，使同一套经过测试的传输页面可以在 Windows 和 iPhone 上复用。后续
Windows 桌面外壳负责托盘、开机自启和资源管理器集成。HTTP 服务仍是传输状态的事实来源，
因此即使桌面外壳不可用，也可以通过浏览器或快捷指令完成操作。

## 分享模型

一次多选操作创建一条 `share` 记录，记录包含一个或多个 `file`。分享具有不透明的公开
token、过期时间、撤销状态和有界文件列表。公开 token 只授权访问这一条分享，不能替代
设备配对凭据。

必要状态：

```text
created -> active -> completed / expired / revoked
                  \-> failed
```

每个文件保存安全的展示名、大小、MIME 类型、SHA-256 校验和、传输进度和服务端源文件句柄。
对客户端返回的 JSON 不能暴露不受限制的本机绝对路径。

## Windows 分享流程

1. 打开“文件分享”页面。
2. 通过文件选择器多选，或把文件拖拽到拖放区域。
3. 审查待分享文件，可逐条移除或清空本次选择。
4. 创建一次分享；页面显示二维码、URL、过期时间和可折叠文件表格。
5. 可撤销单条分享，也可以一键清除当前分享。
6. 在分享表格中查看每个文件的状态、字节数、速度、校验和和错误。

## 移动端下载流程

二维码打开移动端 HTML 页面，页面列出分享和文件。文件链接使用分享 token 并支持 HTTP
`Range`。页面不能假设 iOS 可以静默保存任意文件：浏览器的下载/分享面板才是用户保存
文件的入口。图片可以内联预览，其他文件使用下载链接。

## 移动端上传流程

同一类页面可以提供接收 token 和多文件选择器。浏览器按有界分片使用 `Content-Range`
上传；中断后先询问服务端已提交偏移量，再从该位置继续。Windows 将文件写入配置的接收
目录，并记录最终校验和与文件名。自动接受设置默认关闭。

## 传输契约要求

- 下载支持 Range 时返回 `206`、`Content-Range`、`Accept-Ranges` 和稳定校验和。
- 上传分片携带 `Content-Range: bytes start-end/total` 以及分片或整文件哈希。
- 续传状态返回已提交偏移量和传输状态。
- 重复提交同一个已提交分片必须幂等；重叠或非法 Range 必须拒绝。
- 只有服务端验证完整文件 SHA-256 后才算完成。
- 临时文件不能作为已完成文件暴露，成功后使用原子重命名。
- 分享和上传会话都必须过期，也可以显式撤销或取消。
- 文件数、单文件大小、分享总大小、分片大小、文件名长度和存储配额都必须有上限。
- 服务端路径必须限制在配置的分享目录/接收目录内，拒绝路径穿越和符号链接逃逸。
- 日志可以记录 ID、大小、状态和错误，但不能记录内容、token 或完整私有路径。

## 桌面页面

### 文件分享

必须有三个可见区域：二维码/URL 分享结果、文件选择/拖放区域、当前分享表格。一次多选
显示为一条可展开的分享记录，展开后显示子文件记录。

### 接受记录

显示已接收文件和上传会话：时间、来源设备/分享、目标文件名、大小、校验和状态、续传状态
和失败原因。支持重试、在文件夹中显示，以及在平台允许时执行隐私删除。

### 设置

设置分为软件行为、安全和通知：开机自启、关闭最小化到托盘、资源管理器右键菜单、恢复
默认设置、自动接受、通知声音、接收声音和发送声音。设置要原子持久化；有效配置接口不能
暴露密钥。

## 发布门禁

在 v1.0 前必须完成并测试：Windows 到 iPhone 下载、iPhone 到 Windows 上传、多文件分享、
二维码扫描、HTTP URL、中断/续传、撤销/过期、校验和错误、路径穿越拒绝、设置持久化和
干净重启恢复。
