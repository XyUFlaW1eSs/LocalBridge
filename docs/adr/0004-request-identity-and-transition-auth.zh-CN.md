# ADR 0004：请求标识与过渡认证

[English version](0004-request-identity-and-transition-auth.md)

## 状态

Phase 2 Sprint 2.1 已接受。

## 决策

每个 HTTP 请求都会获得一个受长度限制的 `X-Request-ID`。客户端可以提供该值；缺失时由服务端生成随机 ID。
该 ID 会在响应 Header、系统响应、错误响应和请求日志中返回/记录。

服务端支持在 `security` 下配置可选的 Bearer Token。健康检查继续免认证，以便本地诊断；当 `auth_enabled` 为 `true`
时，其他 API 都需要 Token。Token 使用常量时间比较，且不会写入日志。

## 理由

请求标识让客户端、日志和未来的对端传输可以关联故障。Token 是 Phase 2 的过渡机制：它先关闭当前未认证局域网边界，
但不提前设计最终的配对体验。后续设备注册表和配对流程会通过明确机制配置、轮换和撤销凭据。

## 影响

- 认证默认关闭，因此现有 v0.1 配置保持兼容。
- 部署文档必须提醒用户不要公网暴露，并说明如何启用强 Token。
- 后续客户端报告错误时必须保留请求 ID。
- v1.0 前必须用配对机制替代直接编辑 Token。
