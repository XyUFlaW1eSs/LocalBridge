# ADR 0008：通用 Envelope 与持久化任务状态

[English version](0008-generic-envelope-and-job-store.md)

## 状态

Phase 3 Sprint 3.1 已接受。

## 决策

跨设备工作使用 `Envelope` 表示，每次面向具体对端的投递使用持久化 Job 跟踪。Job 具有明确状态、载荷/存储边界、保留
策略和状态转换规则。当前实现使用带版本的 JSON 存储，由 Go API 隔离文件格式；功能模块不能依赖文件格式。

尽力而为的剪贴板转发器负责创建和更新 Job。已完成的 Job ID 具有幂等性；失败 Job 可被查询，为未来重试保留，但本 Sprint
不会自动重试。

## 理由

直接从事件调用 HTTP 无法解释失败，也无法在重启后恢复。持久化任务边界可以让文件、URL、通知和图片共享投递语义，同时
让各模块保留自己的载荷校验。

## 影响

- Job 载荷可能包含私密剪贴板数据，因此需要保留和访问控制。
- 当前有界负载适合使用 JSON 文件，但它不是高并发数据库；未来可以把存储接口替换为 SQLite。
- Phase 3 在声称可靠同步前，必须增加幂等重试、离线重放、回执、排序和冲突策略。
