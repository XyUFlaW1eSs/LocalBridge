# LocalBridge 路线图

[English version](roadmap.md)

本文档是[产品规划与能力地图](product-plan.zh-CN.md)的详细交付计划。根目录的
[ROADMAP.zh-CN.md](../ROADMAP.zh-CN.md)是简要状态摘要。

## 产品方向

LocalBridge 不应停留在“Windows 与 iPhone 剪贴板同步器”。它的长期目标是一个本地优先、模块化、可插拔的
局域网跨设备协作平台。稳定的产品边界应当是：可信设备网络、通用内容/动作传输层，以及剪贴板、文件、URL、
图片、通知等可以独立演进的功能模块。

平台应该在“一台 Windows 主机 + 一台手机”时足够简单，同时抽象上支持多设备、间歇性连接和多种内容类型。

## 状态与版本线

| 版本 | 阶段 | 状态 | 结果 |
|---|---|---|---|
| `v0.1.0` | Phase 0 + Phase 1 / Sprint 1 | 已交付 | Windows 文本剪贴板桥接和 iPhone Push/Pull 快捷指令 |
| `v0.2.x` | Phase 2 | 进行中 | Sprint 2.1 已交付请求 ID/能力/认证；信任、发现和生产基础设施仍待完成 |
| `v0.3.x` | Phase 3 | 进行中 | Sprint 3.1 已交付 Envelope/Job 存储；重试、历史和富剪贴板仍待完成 |
| `v0.4.x` | Phase 4 | 进行中 | Sprint 4.2A–4.2D GUI、Windows 外壳、接收确认与原生宿主已交付；URL、图片仍待完成 |
| `v0.5.x` | Phase 5 | 计划中 | 其他客户端与设备适配器 |
| `v0.6.x` | Phase 6 | 计划中 | 自动化、托盘/服务体验和插件 SDK |

版本号是方向性建议。一个 Phase 可以包含多个 Sprint 和版本；只有验收标准和发布门禁都通过，Phase 才算完成。

## 阶段规划

### Phase 0 — 核心基础（已交付）

- 仓库结构、Go Module 和跨平台构建基线。
- 配置、结构化日志、生命周期管理和 HTTP Server。
- 模块契约与非阻塞 EventBus。
- 架构、协议、部署、开发及中英文文档。

### Phase 1 — 剪贴板 MVP（已交付）

- Windows Unicode 文本剪贴板读写适配器和序列号监听器。
- 面向 iPhone 快捷指令的局域网 HTTP Push/Pull API。
- Device ID、SHA-256 去重和反馈循环抑制。
- 运行诊断、测试和可运行的 `v0.1.0` 发布包。

### Phase 2 — 平台加固、信任与发现（进行中；Sprint 2.1–2.5 已交付）

目标：在增加更多载荷类型前，让平台安全、可诊断、可维护。

计划工作：

- 配置 Schema 版本化、默认值、迁移规则和脱敏配置诊断。
- 稳定错误信封、请求 ID、API 能力接口和兼容性测试。
- 设备身份、配对流程、令牌存储、允许列表、撤销/重置和安全的首次运行体验。
- Sprint 2.2 已提供显式 pairing code 流程、持久化对端注册表和撤销/列表接口；peer Token 认证和自动配置仍待完成。
- Sprint 2.3 已提供可选 UDP 发现和临时不可信可达性列表；对端健康、认证出站传输和自动配置仍待完成。
- Sprint 2.4 已让启用认证时的受保护 HTTP 边界接受已配对 peer Token；过期、轮换和面向用户的自动配置仍待完成。
- Sprint 2.5 已提供对端能力探测和本地剪贴板尽力而为转发；持久化同步、重试、回执和离线重放仍属于 Phase 3。
- 通过 mDNS 或 UDP 广播进行局域网发现，并保留手动 IP/端口回退方式。
- 对端设备注册表，记录在线状态、最后出现时间、能力以及网络变化后的恢复。
- TLS 或等价的认证本地通道；已配对链路不能静默降级到不安全模式。
- 所有模块共享的重试、超时、限流和载荷大小策略。
- 明确持久化边界：哪些数据跨重启保留、保留多久、是否加密以及如何删除。
- Windows 防火墙/服务/托盘安装设计、健康诊断和支持信息包。

退出标准：两台已配对设备可以互相发现、认证、报告能力并提供有用诊断；未配对流量会被拒绝；配置和升级行为
都有文档和测试。

### Phase 3 — 通用同步引擎、富剪贴板与历史（进行中；Sprint 3.1 已交付）

目标：不要让每个模块重复发明自己的同步语义。

Sprint 3.1 已提供通用 Envelope、有边界的持久化 Job 存储和只读任务查询；当前只包装剪贴板出站，尚不承诺可靠投递。

计划工作：

- 通用 `Envelope`：事件 ID、来源设备、内容类型、MIME 类型、hash、大小、时间、TTL、优先级以及可选的回复/关联 ID。
- 能力协商与内容回退，例如图片无法支持时回退到预览或文本元数据。
- 幂等投递、排序规则、冲突策略和按设备同步过滤器。
- 出站对端传输，使 Windows 变化可以主动送达，而不要求手机反复 Pull。
- 有界剪贴板历史、搜索、置顶/删除/清空和隐私保留策略。
- 支持图片剪贴板格式、HTML/RTF（平台允许时）、截图和格式转换。
- 通过存储接口提供持久化、迁移以及导出/导入。

退出标准：已配对手机或桌面客户端可以通过认证的出站路径接收 Windows 剪贴板变化；富内容能够安全降级；历史记录
遵循配置的重启策略；重复和冲突测试通过。

### Phase 4 — 局域网协作模块（进行中；Sprint 4.2D 已交付）

目标：传递工作上下文，而不只是剪贴板文本。

Sprint 4.2A 已交付内嵌浏览器 GUI、安全 multipart 多文件分享、接收记录界面、本地真实二维码 PNG 和版本化设置持久化。
Sprint 4.2B 基础现已实现当前用户级 Windows 开机启动与 Explorer 设置同步、原生托盘、Explorer 多文件分享命令和有边界的完成通知。
Sprint 4.2C 已实现关闭自动接收时持久化的等待/允许/拒绝流程。Sprint 4.2D 已加入 WebView2 宿主并通过关闭到托盘与托盘恢复实测；
系统浏览器保留为明确回退路径。

计划模块：

- 文件传输：元数据、缩略图、分块、校验和、进度、暂停/恢复/取消、过期和安全目标路径。
- 文件分享批次模型：一次多选创建一条可展开的分享记录；二维码和 HTTP URL 指向同一个有过期时间的公开页面。
- 移动端优先的下载/上传页面：iPhone 使用浏览器保存/分享行为，并通过 `Range`/`Content-Range` 恢复中断传输。
- Windows GUI：文件分享、接受记录、设置三个页面。首个 UI 切片采用 Web-first，使传输契约可在 Windows 和
  iPhone 上测试；Windows 外壳负责托盘、开机自启和资源管理器右键菜单。
- 设置：关闭最小化到托盘、自动接受、通知声音和恢复默认设置。
- URL 推送：标题/预览元数据、浏览器接力以及可选的 URL 隐私控制。
- 图片作为一等载荷，包括压缩和大小阈值。
- 通知推送：等级、过期、确认和动作载荷。
- 截图捕获/发送与“发送当前上下文”组合动作。
- 统一传输/任务状态 API：排队、进行中、完成、失败和取消。

退出标准：已配对的可信局域网设备可以双向发送文件和 URL，支持恢复和完整性校验；多文件二维码/URL 分享可在
iPhone 上工作；接受记录和设置可持久化；Windows GUI 可以创建/撤销分享；通知有边界且可观测；模块之间不直接互相依赖。

### Phase 5 — 多客户端与设备生态

目标：让协议不再局限于一个 Windows 主机和 iPhone 快捷指令。

- 在后台和通知能力足够支持时，提供原生 iOS/iPadOS 客户端。
- Android 客户端，支持系统分享面板并明确前台/后台策略。
- macOS 适配器，覆盖 NSPasteboard、通知、文件和登录启动。
- Linux 适配器，处理 Wayland/X11 剪贴板差异、通知和服务启动。
- Windows 托盘模式与 Windows Service 模式，清楚说明两者对剪贴板访问的取舍。
- 无头 CLI 和只读 Web 诊断页；Web UI 不得成为绕过配对 API 的安全通道。
- 设备角色、多台 Windows 主机、按设备订阅，以及“发送到指定设备”和“广播到设备组”。

退出标准：至少两个非 Windows 客户端可以按照文档协议互操作；能力协商有效；平台限制会明确呈现给用户。

### Phase 6 — 自动化、集成与插件 SDK

目标：把平台变成可组合的本地工作流引擎。

- 稳定的插件 Manifest、能力声明、生命周期钩子、配置命名空间、权限模型和版本兼容规则。
- CLI 命令、快捷键、命令面板和自动化规则，例如“收到 URL 后在浏览器打开”或“收到截图后保存到目录”。
- 浏览器扩展、系统分享目标和面向本地应用的 Webhook。
- 面向敏感动作的事件过滤、转换和审批门。
- 社区模块的签名、审核和沙箱预期。

退出标准：第三方模块可以基于 SDK 开发而不修改核心组合代码；权限与升级行为明确。

### Phase 7 — 稳定平台版本（`v1.0.0`）

- 冻结并文档化 `v1` 协议兼容策略。
- 安全默认值、威胁模型、安全审查、模糊测试和依赖审计。
- 签名安装包/产物、可选自动更新、回滚和迁移工具。
- 剪贴板延迟、文件吞吐、内存和磁盘保留的性能预算。
- 崩溃恢复、离线队列恢复、可观测性和支持信息包。
- 完整的中英文用户/开发者文档、示例客户端、协议一致性测试和发布清单。

## 原规划之外值得实现的高价值能力

这些能力的价值在于强化平台，而不是增加孤立功能：

- **能力协商：** 传输前先声明客户端能读写什么，避免富内容破坏旧客户端。
- **离线队列与投递回执：** 明确显示载荷是排队、已送达、被拒绝还是过期，不让用户根据超时猜测结果。
- **选择性同步：** 按设备订阅、内容过滤和隐私规则，避免每台设备收到所有剪贴板内容。
- **历史与隐私控制：** 搜索很有用，但剪贴板可能包含密码，因此必须有保留、脱敏和一键清除。
- **组合上下文传输：** 将 URL、截图、选中文本和来源元数据作为一个任务发送，更接近真实跨设备工作。
- **诊断与一致性工具：** CLI/支持包和协议测试套件可以降低添加客户端和排查家庭网络问题的成本。
- **安全自动化：** 事件过滤、审批、TTL 和权限可以提供强大工作流，又不把配对设备变成无限制远程控制入口。
- **优雅降级：** 客户端无法渲染原始 MIME 类型时，应收到预览或文本回退。
- **隐私友好的遥测：** 默认不上传云遥测；如果未来增加，必须选择加入、本地优先且不含内容。
- **多主机路由：** 让笔记本、台式机和家庭服务器共存，同时避免重复循环和含义不清的“latest”状态。

## 依赖顺序

```text
信任 + 发现
      ↓
通用信封 + 能力协商 + 出站传输
      ↓
持久化 + 历史 + 冲突/离线策略
      ↓
富剪贴板
      ↓
文件 / URL / 图片 / 通知
      ↓
更多客户端
      ↓
自动化 + 插件生态 + v1 加固
```

只有在不绕过上游契约时，功能才可以并行开发。例如可以提前做文件传输 UI 原型，但正式文件投递必须等待共享的
信任、传输、校验和任务状态契约。

## 优先级

- **P0 — 平台安全：** 配对、认证、协议兼容、防数据丢失、损坏检测、恢复和隐私控制。
- **P1 — 核心用户价值：** 自动出站剪贴板、富剪贴板、历史、文件、URL、通知和前两个额外客户端。
- **P2 — 采用与效率：** 托盘体验、分享面板、浏览器扩展、CLI、规则、截图和组合上下文。
- **P3 — 实验：** 云中继、公开插件市场、AI 转换，以及会增加外部服务或显著安全范围的功能。

选择功能时，综合评估用户价值、对平台的杠杆作用、安全风险、依赖影响和可测试性。优先做能解锁多个模块且保持本地
优先的工作。

## Sprint 与发布门禁

每个 Phase 拆分为若干个具有可演示结果的 Sprint。每个 Sprint 必须记录：

1. 问题陈述和用户场景。
2. 范围、非目标和依赖假设。
3. 公共契约、数据模型以及安全/隐私影响。
4. 实现方案和测试策略。
5. 文档与配置变化。
6. 验收证据、已知限制和后续工作。

Phase 发布前必须满足：

- 单元测试、集成测试、跨平台构建和相关手工局域网测试通过。
- 协议兼容性测试以及错误/异常路径测试通过。
- 对新增网络、存储、执行或权限行为进行安全审查。
- 根据载荷大小完成相应的性能和资源检查。
- 英文/中文文档、示例、变更日志和回滚说明已更新。
- 产出可从干净目录运行的发布包。

## 非目标与护栏

- 核心工作流不能依赖云账号或厂商中继。
- 不要承诺平台不允许的 iOS 后台常驻服务；使用快捷指令或明确生命周期约束的原生客户端。
- 不要把未认证的局域网 API 暴露到公网。
- 功能模块不能直接导入彼此；使用契约和事件通信。
- 默认不要无限期保存剪贴板/文件内容。
- 在投递状态和错误行为定义前，不要把单向 Demo 称为“同步”。
