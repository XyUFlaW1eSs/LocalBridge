# 产品规划与能力地图

[English version](product-plan.md)

## 最初的想法

LocalBridge 最初解决的是一个实用问题：在可信局域网中，把 Windows 电脑与 iPhone 之间的剪贴板内容传递起来。
更大的产品想法是：

> 打造一个本地优先、模块化、可插拔的跨设备协作平台，而不是一个单用途的剪贴板同步器。

平台应该让一台设备成为另一台设备的有用延伸，同时不要求云账号。文本剪贴板是验证传输、设备和模块边界的第一
个证明，不是最终的产品边界。

## 产品原则

- 默认本地优先；云中继永远不是核心工作流的前置条件。
- 设备、传输和能力是三个不同概念。
- 每个载荷都要明确所有权、投递状态、完整性和保留行为。
- 模块负责领域行为；核心负责生命周期、信任、传输和策略。
- 即使多设备设计不断扩展，单主机的最简单安装仍应保持简单。
- 隐私是产品能力：本地数据必须有保留、过滤和清除控制。
- 客户端会受操作系统限制；协议应暴露限制，而不是假装所有平台行为相同。

## 用户与高价值场景

| 用户 | 场景 | 价值 |
|---|---|---|
| 手机 + 电脑的个人用户 | 在任一设备复制文本、URL、图片或文件并在另一台设备使用 | 减少给自己发消息和上传云盘的重复动作 |
| 开发者 | 在机器之间发送链接、堆栈、截图或测试产物 | 在调试和研究中保留上下文 |
| 家庭/办公用户 | 通知其他设备、分享文件或向指定设备发送动作 | 把局域网变成个人工作空间 |
| 高级用户 | 通过快捷键、快捷指令、浏览器或 CLI 触发规则 | 把重复操作变成本地自动化 |
| 集成开发者 | 不改核心就能添加客户端或模块 | 让平台通过适配器持续增长 |

## 头脑风暴能力清单

### 平台基础能力

- 设备身份、配对、撤销、信任重置和人类可读的设备名称。
- mDNS/UDP 发现，以及针对屏蔽组播网络的手动回退方式。
- 通用内容/动作信封：MIME 类型、能力要求、hash、大小、TTL、优先级、来源和关联 ID。
- 能力协商和安全的预览/降级。
- 出站投递、确认、重试、过期、离线队列和取消。
- 端到端完整性校验、分块/断点续传和限流。
- 支持迁移的持久化、有界保留、导入/导出和隐私删除。
- 冲突策略：最后写入优先、询问用户、按设备偏好或追加到历史。
- 诊断 CLI、支持包、协议一致性测试和网络模拟测试。

### 内容与协作模块

- 文本、图片、HTML/RTF 和截图剪贴板。
- 剪贴板历史、搜索、置顶、脱敏和一键清除。
- 文件/目录传输、安全目标路径、预览、恢复和进度。
- URL 推送、元数据预览、浏览器接力和“在指定设备打开”。
- 通知推送：等级、过期、确认和动作按钮。
- “发送上下文”组合任务：选中文本、URL、截图和来源元数据。
- 设备间笔记、小片段和临时消息。
- 设备在线状态和指定设备发送，但不把平台变成聊天应用。

### 客户端与集成

- 先支持 iPhone/iPad 快捷指令；当后台/通知需求足够明确时再提供原生 iOS 客户端。
- Android 系统分享面板与通知集成。
- Windows 剪贴板/托盘/服务模式，并清楚记录行为取舍。
- macOS Pasteboard 与 Linux Wayland/X11 适配器。
- 无头 CLI、只读诊断网页、浏览器扩展和本地 Webhook。
- 快捷键、命令面板、系统分享目标和脚本 API。

### 可靠性、隐私与运维

- 安全默认值、禁止未认证公网暴露、令牌轮换和审计事件。
- 只允许不含内容的选择加入式遥测；默认日志不包含载荷正文。
- 崩溃恢复、队列恢复、安全关闭和明确的部分传输语义。
- 签名产物、安装器/服务注册、升级、回滚和版本兼容。
- 内存、磁盘保留、CPU、剪贴板延迟和文件吞吐预算。

## 不应过早实现的内容

- 云账号、强制中继或常驻远程服务。
- 与平台重点协作目标竞争的通用聊天/社交层。
- 没有窄能力边界和明确审批模型的任意远程命令执行。
- 在插件 Manifest、权限、签名和兼容性未定义前建立插件市场。
- 在协议、设备信任和投递状态可靠前先做复杂 UI。

## 产品成功信号

当以下事实成立时，平台才算真正进步：

1. 新设备无需阅读源码就能完成配对和诊断。
2. 新模块可以复用信任、传输、任务状态和策略，而不用重复实现。
3. 用户可以解释每个载荷的状态：排队、送达、拒绝、过期、取消或失败。
4. 不支持的格式会安全降级，不会静默损坏数据。
5. 发布包可以从干净目录安装、升级、回滚和恢复。
6. 用户能够查看并删除已保留的私密内容。
