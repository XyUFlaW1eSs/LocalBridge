# Sprint 2.1 — 协议与安全基础

[English version](sprint-2.1.md)

## 目标

在实现设备配对和发现前，让 Phase 2 流量可诊断，并提供向后兼容的认证边界。

## 范围

- 有长度限制的请求 ID、响应传播和结构化请求日志。
- 用于能力协商基础的 `GET /api/v1/system/capabilities`。
- 对非健康接口提供可选 Bearer Token 保护。
- 安全配置和部署说明。

## 非目标

- 自动配对、Token 轮换或设备撤销。
- 局域网发现或设备间出站投递。
- TLS 终止或持久化设备注册表。

## 验收标准

- 没有 `security` 配置段的现有 v0.1 配置仍可启动。
- 配置 Token 后，能力和功能接口受保护，而健康检查仍可访问。
- 缺失或无效 Token 返回带请求 ID 的 `401`；有效 Token 请求成功。
- 客户端可以在使用能力前查看版本、设备身份和能力列表。
- Token 不写入日志，比较使用常量时间算法。
- 单元测试、`go vet`、文档和部署示例通过审查。

## 验证

```text
go test ./...
go vet ./...
git diff --check
```

## 后续工作

Sprint 2.2 应实现设备身份持久化、配对、Token 配置/撤销和设备注册表。直接编辑 YAML Token 是临时方案。
