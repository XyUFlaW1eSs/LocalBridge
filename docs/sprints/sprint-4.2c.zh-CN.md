# Sprint 4.2C — 接收确认流程

[English](sprint-4.2c.md)

## 状态

已交付。原生宿主窗口后续已由 Sprint 4.2D 交付。

## 目标

让 `auto_accept` 设置成为真实安全边界，同时不破坏手机端断点续传。手机先提交受限元数据，只有策略允许后才接收文件字节。

## 已交付契约

- 上传具有持久化的 `pending`、`active`、`completed`、`failed` 和 `rejected` 状态。
- 当 `auto_accept=false` 时，创建上传返回 HTTP `202` 和 `pending`。公开手机页面轮询受能力 Token 保护的状态 URL，等待期间不发送文件字节。
- `POST /api/v1/files/uploads/{upload_id}/approve` 与 `/reject` 只允许本机回环或已认证管理请求；批准后继续使用现有
  `Content-Range` 断点续传流程。
- “接受记录”为等待项提供明确的“允许”和“拒绝”操作。
- 仅含元数据的 `file.receive_requested` 事件会产生 Windows 托盘通知；事件只含上传 ID 与声明大小，不含能力 Token、路径或文件内容。
- 使用相同幂等键重试创建会返回同一记录，不会重复发布请求通知。

## 安全与恢复

等待上传会预留配额，但不会创建部分文件；批准前写入分片返回 `409`。拒绝是终态，发送页面可以看到明确结果。
等待与活动记录都遵循配置的上传 TTL，并通过现有状态存储跨进程重启保留。

## 验证

自动化测试覆盖等待创建、重复事件抑制、批准前写入拒绝、远程未认证批准拒绝、本机批准并完成，以及明确拒绝。
完整 Go 测试/静态检查、前端语法检查、Windows 发布构建和 Linux 编译门禁均通过。
