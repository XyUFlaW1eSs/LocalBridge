# 工程开发流程与子任务职责

[English](engineering-workflow.md)

## 目的

LocalBridge 是一个长期演进的平台。主任务负责产品方向、架构、契约、优先级和验收；
名为 `程序开发` 的子任务负责主任务明确下发的实现工作。任何角色都不能擅自改变产品
范围，也不能在缺少证据时把功能称为完成。

## 角色职责

### 主控任务

- 在下发任务前审查当前仓库。
- 将产品目标拆成有依赖顺序的小任务包。
- 在实现前定义 API、存储、安全、用户体验和兼容性契约。
- 在隔离 worktree 中向 `程序开发` 下发实现任务。
- 审查差异、测试、安全边界、文档和用户可见行为。
- 只集成通过验收门禁的改动，并对不完整实现继续下发聚焦任务。

### `程序开发` 子任务

- 检查现有代码并保持已有行为兼容。
- 只实现当前任务包，不擅自扩展范围。
- 为正常、失败、重启、安全和恢复路径补充测试。
- 保持英文和中文文档同步。
- 在报告完成前运行格式化、测试、vet 和构建。
- 每个可独立审查的切片提交清晰 commit，并报告 commit ID 和已知缺口。

## 任务包格式

每个实现任务必须说明：

1. 用户可见的结果。
2. 受影响的包、路由、存储和配置。
3. 安全与隐私限制。
4. 与现有模块的兼容要求。
5. 必须执行的测试和手工验收步骤。
6. 必须更新的文档。
7. 本切片明确不包含的内容。

## 审查门禁

实现切片不能只因为“能编译”就算交付。主控按以下顺序检查：

```text
契约审查
    -> 代码差异审查
    -> 单元测试与 HTTP 集成测试
    -> go vet 与构建
    -> 安全 / 数据丢失审查
    -> 手工用户流程验证
    -> 双语文档与变更记录
```

文件传输切片还必须测试中断恢复、Range 校验、校验和、过期/撤销、路径穿越和重启恢复。
GUI 切片还必须测试干净环境启动、拖拽或文件选择、托盘/关闭行为、设置持久化和移动端
视口可用性。

## Worktree 与提交策略

子任务在独立 Git worktree 中工作。提交应保持小而清晰。主控审查 commit 后再集成；
生成数据、凭据、本地配置和构建产物不得提交。

## 当前执行顺序

1. 文件分享与断点传输协议，以及持久化状态。
2. 移动端下载/上传网页和二维码元数据。
3. 桌面 Web GUI：文件分享、接受记录和设置。
4. Windows 打包：托盘、关闭最小化、开机自启和资源管理器右键菜单。
5. 通知、声音、传输恢复和端到端测试。
6. 安全审查、性能测试、双语发布文档和 v1.0 门禁。
